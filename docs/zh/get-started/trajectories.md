# Agent 轨迹

Managed Agents 不只返回最终答案。它会保留 Agent 工作时经历的步骤：消息、模型输出、
工具调用与结果，以及执行完成事件。当这些记录围绕一个任务组织起来时，它们就描述了一条
**Agent 轨迹（trajectory）**。Outcome 是一个独立标签，用来说明这条轨迹是否产生了有用或正确的结果。

轨迹与 outcome 一起把生产执行与模型改进连接起来。运行时记录执行过程，评估为行为添加标签并筛选有价值的样本，
后训练从选中的样本中学习，得到的新模型再回到运行时。

## 一个任务的完整记录

![一个任务进入 Managed Agents 运行时；模型与工具和环境反复交换动作与观察，直到产生结果。上下文、决策、动作、观察和结果组成轨迹；独立的 outcome 标签记录它是否有用或正确，两者共同支持评估和后训练。](https://assets.yesy.site/f/images/2026/09/gqzh1y9q.png)

[查看 Agent 轨迹图原图](https://assets.yesy.site/f/images/2026/09/gqzh1y9q.png)

**轨迹**是 Agent 完成一个任务时经历的有序路径，从初始上下文开始，到产出结果结束。
它包含的信息比对话记录更多。

| 组成部分 | 记录的内容 |
|---|---|
| **任务与上下文** | Agent 被要求做什么，以及它可以使用的状态。 |
| **决策** | 选择下一步动作或产生答案的模型响应。 |
| **动作** | Agent 发起的工具调用。 |
| **观察** | 工具结果、命令输出、错误和其他环境反馈。 |
| **产出** | 任务产生的答案、文件、artifact 或外部变更。 |

这里的**决策**是指记录下来的模型响应和可观察的动作选择，不代表模型或 API 没有暴露的私有思考链。

**Outcome** 是关联到轨迹上的质量或业务信号，不是轨迹内部的另一个步骤。对于一个销售报告任务，
报告文件是产出；outcome 可以记录它的合计是否通过确定性检查、审核者是否接受，或者报告是否满足评估 rubric。

::: info 轨迹不会自动成为训练数据
一条没有 outcome 的轨迹仍然是有效的 Agent 行为记录。只有关联相应的 outcome，并完成必要的筛选和数据治理后，
它才会成为带评分的评估样本或候选训练样本。

`run.finished` 事件只说明运行如何结束：`succeeded`、`failed` 或 `aborted`。它不是质量分数。
一次运行可以成功结束，但仍然产生错误或无用的答案。Outcome 必须代表对该任务真正重要的标准。
:::

## Session events、轨迹与 trace

这些术语描述同一次工作的不同视图。

| 术语 | 在本文档中的含义 | 公共 API 对应面 |
|---|---|---|
| **Session** | 与一个 Agent 的持久化对话，可以包含多个回合。 | 使用 `agent_id` 和 `session_id` 定址的资源。 |
| **回合** | 一条用户消息以及 Agent 对它完成的工作。 | 通过 `run.started` 和 `run.finished` 观察；没有独立的 Run 资源。 |
| **Event** | Session 内一条持久保存、按序排列的记录。 | 通过事件列表或可续传的 SSE 流读取。 |
| **轨迹** | 贯穿上下文、模型输出、动作、观察和产出的任务级有序路径。 | 从 Session 记录中组装的概念，不是一等资源。 |
| **Trace / span** | 将记录下来的执行步骤分组的可观测性视图，通常包含耗时和状态。 | Managed Agents 公共 API 不暴露 trace 和 span 对象。 |

Trace 用于检查执行如何运作；轨迹用于把这次行为作为一条任务级路径进行分析。关联 outcome 后，
它可以成为评估样本、偏好信号或强化信号。同一次执行可以同时贡献给这两个视图，但两个术语不能互换。

当前，可以通过任一个 SDK 读取完整、有序的事件历史和持久保存的对话记录：

- **TypeScript：**`listAllEvents(agentId, sessionId)` 和
  `getSession(agentId, sessionId, { history: true })`。
- **Python：**`list_all_events(agent_id, session_id)` 和
  `get_session(agent_id, session_id, history=True)`。

请将你自己的任务标识、产出引用和 outcome 与这些记录一起保存。

::: info 在应用中保存 Outcome
Managed Agents 记录这个闭环的运行时部分。请在应用中把 outcome 标签和数据集归属与 Agent、Session id 一起保存，再把整理后的数据交给训练流程。
:::

## Outcome 让轨迹变成学习数据

轨迹说明发生了什么。Outcome 说明这种行为是否值得重复。没有第二个信号，失败和高质量示例在结构上可能完全一样。

Outcome 可以来自：

- **确定性检查**，例如测试通过，或某条记录达到预期状态。
- **Rubric 评估器**，按照书面标准为结果评分。
- **人工判断**，例如接受、拒绝，或比较两个结果。
- **业务信号**，例如客服工单已解决，或业务流程已完成。

请将 outcome 的来源和评估器版本与标签一起保存。如果缺少评分标准，评估器更改后就无法复现或比较得分。
在使用生产轨迹进行训练前，删除密钥和训练流程无权保留的数据。

## 生产执行与后训练形成闭环

![一个六阶段闭环：将模型部署到 Managed Agents 运行时，执行真实任务，收集带 outcome 的轨迹，对它们进行评估和筛选，完成后训练，再将新模型版本部署回运行时。](https://assets.yesy.site/f/images/2026/09/8ljp3d8r.png)

[查看模型改进闭环原图](https://assets.yesy.site/f/images/2026/09/8ljp3d8r.png)

外层闭环跨越多个任务：

1. **部署模型。** 配置 Agent 在托管运行时中使用某个模型。
2. **执行真实任务。** 模型使用应用提供的工具、权限、文件和环境完成工作。
3. **保留带 outcome 的轨迹。** 保存有序执行记录，并关联用于判断结果好坏的信号。
4. **评估与筛选。** 找到成功行为、重复失败，以及安全且适合训练的示例。
5. **后训练。** 高质量轨迹可以转化为监督学习示例；结果对比可以转化为偏好数据；具有可验证 outcome 的任务可以提供强化信号。
6. **部署新模型版本。** 让它在相同任务环境中运行，比较 outcome，然后开始下一轮。

这种连续性很重要。训练数据反映模型在生产环境中真正使用的工具和收到的反馈，改进后的模型也会回到这些运行条件中。
因此，Managed Agents 既是 Agent 完成工作的执行层，也是产生结构化行为记录、用于改进后续模型的地方。

## 需要保留的信息

对于每一个可能形成轨迹的任务，请保留：

- 稳定的任务标识，以及对应的 `agent_id` 和 `session_id`；
- 完整、有序的事件历史，而不只是最终的 assistant 消息；
- 评估任务所需的产出或 artifact 引用；
- outcome 标签、来源和评估器版本；
- 足以复现当时条件的 Agent、模型、工具和环境版本信息。

Managed Agents API 不会在一个对象中提供所有字段。请将应用自有的部分保存在你的数据库中，
并与从 ZooWork 读取的 Session 记录关联。

## 检查你的理解

::: details 轨迹和 Session 是同一个东西吗？
不是。Session 是持久化对话，可以包含多个回合或任务。轨迹是一个任务的有序行为路径，outcome 可以单独关联到这条路径上。
:::

::: details 轨迹包含模型的私有思考链吗？
不一定。在本文档中，轨迹包含记录下来的模型输出、可观察动作和环境反馈。不要推断模型或 API 没有暴露的推理过程。
:::

::: details `run.finished` 的状态是 `succeeded`，就表示任务产生了好结果吗？
不是。它描述运行如何结束，而不是结果是否满足任务的质量或业务标准。请单独关联 outcome 信号。
:::

::: details Managed Agents 当前会运行后训练任务吗？
不会通过公共 API 运行。Managed Agents 记录生产执行历史；你的应用当前负责 outcome 标签、数据集准备和后训练流程。
:::
